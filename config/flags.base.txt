# Compiler flags per source prefix, for tools/compile_cpp.sh. The longest
# prefix that matches the source path wins; flags apply to every file under it
# (per directory, never per file or per function). The compiler is the
# prebuilt upstream LLVM 3.6.2 under tools/cc/ (tools/setup.sh); TLG_CXX
# overrides it for experiments (tools/compiler_probe.sh).
#
# Evidence, from the functions matched so far (docs/TARGETS.md has the probe):
#   -O2                             -O1 and -Os lose the vectorised and
#                                   scheduled forms the base has
#   -march=btver2                   the Jaguar: its instruction set is in use
#                                   (movbe 410 times, andn 207, lzcnt 69 in the
#                                   executable)
#   -mllvm -disable-post-ra         upstream's BtVer2Model turns on the post-RA
#                                   list scheduler, which reorders the register
#                                   copies of 0xbc30 and the loads of 0x137c0
#                                   against the base; Sony's compiler did not
#                                   schedule that way (docs/TARGETS.md)
#   -fwrapv                         the base subtracts in 32 bits and then
#                                   sign-extends (0x12120); with signed
#                                   overflow undefined clang widens first
#   -fno-strict-aliasing            the base reloads a field after a store
#                                   through another type (0x12120)
#   -fno-omit-frame-pointer         every non-leaf keeps rbp (push rbp; mov
#   -momit-leaf-frame-pointer       rbp, rsp), every leaf omits it
#   -fPIC                           the executable is position independent
#                                   (ET_SCE_DYNEXEC, 29k relocations); the
#                                   Orbis driver defaults to -fPIC (Sony's 2013
#                                   LLVM dev meeting slides, docs/TARGETS.md)
#                                   and upstream 3.6.2 does not for this triple
#   -fstack-protector-strong        an Orbis driver default (same slides); the
#                                   executable imports __stack_chk_fail and
#                                   __stack_chk_guard
#   -fno-exceptions -fno-rtti       Orbis driver defaults (same slides)
#   -fno-math-errno                 the upstream PS4 toolchain's default
#                                   (IsMathErrnoDefault false)
#   -std=gnu++11                    the Orbis driver's default dialect (slides)
#   -fshort-wchar -D__ORBIS__       the PS4 target's wchar_t is unsigned short
#   -D__PS4__                       and these are its macros (clang 3.7+'s
#                                   PS4 target info); 3.6.2 knows no PS4 target
#
# A line may start with `cxx=<path or tools/cc version>` after the prefix to
# compile that prefix with another release (tools/compile_cpp.sh): the
# executable's components were built in different years (the Havok 2014.2
# nightly of 2014-11-21, the sound engine on 2016-09-30, the game with SDK
# 3.5), so one compiler need not fit all of src/.
#   -ffreestanding -nostdlibinc     no host libc headers; the compiler's own
#   -nostdinc++                     intrinsic headers (xmmintrin.h) stay
src/ --target=x86_64-scei-ps4 -O2 -march=btver2 -mllvm -disable-post-ra -fPIC -fstack-protector-strong -fno-math-errno -fwrapv -fno-strict-aliasing -fno-exceptions -fno-rtti -fno-omit-frame-pointer -momit-leaf-frame-pointer -ffreestanding -nostdlibinc -nostdinc++ -std=gnu++11 -fshort-wchar -D__ORBIS__ -D__PS4__ -Isrc/include
