# tools/

Every file in this directory, with what it does. One tree may carry several
targets (a target is configured when `config/sha256sums.<slug>.txt` exists);
the tools work on the target `tlg_version.py` reports (`VERSION=<slug>`, or
the first configured one, `base`), and the config, base file, build
(`build/<slug>/`) and progress (`docs/<slug>/`) paths follow that slug.
`tools/ext/` and `tools/ghidra/` are fetched by `setup.sh` and not tracked.
`../build.sh` at the repository root runs `setup.sh` and `extract_pkg.sh` when
their output is missing, then `build.sh verify` or `setup` and ninja, whose
last step is the gate.

| tool | what it does |

| `vtable_names.py` | which class each vtable belongs to, where the executable says so: the vtable address point each Havok type-info registration stores beside its type name (by `lea`, or read from a temporary built through the class's finish constructor), into `config/vtables.<slug>.txt`, which the gate resolves `_ZTV<class>` relocations against (docs/DECISIONS.md D12); lists the vtables constructors store that no type info names, with the evidence at hand; `--check` verifies the rows of `config/vtables.derived.<slug>.txt` (vtables named by ruling, D14) against the constructor each cites, and the vtable of every library instantiation the claimed rows are members of (std::function's implementation for a lambda: the rows sit in their slots of one base vtable, a claimed slot-0 row stores its address point; one whose slot 0 is not claimed is listed as pending), and every derived row that `merges` a second class into an address another row holds (below) |
| `rename_rows.py` | `<tu> [--rename OLD=NEW] [--write]`: re-points the symbol column of a unit's rows that name members of a lambda's std::function implementation after the unit renamed the enclosing function (`--rename`) or renumbered its lambdas (`$_<n>` counts the whole file's): compiles the unit, lists its instantiations by (enclosing function, order), and assigns the stale rows' instantiations in order to the object's, taking the one assignment under which every re-pointed row compares equal to the base; refuses none or several; prints without `--write` |

| `gen_ninja.py` | writes `build.ninja`: a `cxx` edge per source under `src/libs/` (`compile_cpp.sh`) to `build/<slug>/obj/<path>.o`, an `ir` edge per source under `src/game/` and one `game_module` edge to `build/<slug>/game/module.o` (`game_module.py`), a `gen_data` edge per row of `config/data_schema.<slug>.txt` (`gen_data_inc.py`, an implicit input of its TU's compile), and the default `gate` target, `check_elf.py --gate` |

| `compile_cpp.sh` | compiles one source with the flags `config/flags.<slug>.txt` gives its longest matching prefix; the compiler is the release the prefix's `cxx=<version>` names (3.3 for `src/libs/`, 3.7.1 for `src/game/`), else `TLG_CXX`, else the host's clang-19; `build/<slug>/` is on the include path for the generated `gen/D_<hex>.inc` files; `--ir` writes a game unit's unoptimised bitcode (and its text) and its stage 1 (the unit's own `-O2` pipeline) for the module, `--codegen <prefix>` runs code generation alone over the linked and optimised module |
| `game_module.py` | builds the game region as one module in two stages (docs/DECISIONS.md D83, which supersedes D50's one pipeline): the stand-in definitions of the game objects no file defines yet (protected, zero-initialised, writable; from `config/modules.<slug>.txt`), `llvm-link` of every unit's stage 1 bitcode and the stand-ins, the local data and every used inline definition made internal (one `opt -internalize` step, the symbol table compared before and after), the link stage's pipeline (`opt -std-link-opts -vectorize-loops -vectorize-slp`, by the `opt` built from the line's patched source) and code generation alone to `build/<slug>/game/module.o`; refuses a name two files define; writes `build/<slug>/game/symbols.txt` (what each unit defines); `--single` the module of one file, for the inner loop. A name the compiler gives (`COMPILER_LOCAL`: clang's array-destroy helper `__cxx_global_array_dtor`, `.1`, ...; a namespace-scope object's initializer `__cxx_global_var_init`, `.1`, ...; a file's `_GLOBAL__sub_I_<file>`) is renamed by the link by one counter over every unit; its row names the unit's own spelling (the unit's IR and single-file object), and `match_check.py` proves the module symbol for it. The local data (`config/local_data.<slug>.txt`, one `<symbol>` per row): a variable the base's optimiser saw as local though every file declares it is given internal linkage in the linked module before the pipeline (`opt -internalize` with every other definition preserved; the module's symbol table before and after must differ by the rows alone), each row proven from the base's code first (`module_boundary.py` `local_proof`); a stand-in for one carries a writer `__standin_writer_<symbol>` storing 1 until a file defines the variable. |
| `module_boundary.py` | writes `config/modules.<slug>.txt` from the base: which addresses of the data are the game's and which the libraries', the CRT's or the GOT's, from a census of every RIP-relative operand by the region of its instruction (a cut per data area, the exceptions carved out); `--check` verifies the file `--local` proves the rows of `config/local_data.<slug>.txt`: every access of the variable in the game's code (a thread-local from its `add rax, [rip+slot]` sites, the address register followed in text order; an ordinary one by its RIP-relative operands) must be a one-bit read (`movzx; and 1`, `mov; xor 1; test 1`, `test byte, 1`), a kept copy, a masked copy put back (`mov r, byte; and r, 1` with `mov byte, r` into the same operand after it, the register and the address unwritten between: the shrunk form of a store of a loaded copy, which GlobalOpt accepts beside the initial value and the one other constant) or a store of 0, 1 or such a copy; a read that compares the whole byte (`cmp byte, 0`) refuses the row with the site. `layout_link.py` runs the same proof over every row in the gate. |
| `fingerprint.py` | compiler fingerprints over the whole disassembly (cdqe vs movsxd, store merging, vzeroupper, ud2 after call, int 0x41, frame pointers by leaf/non-leaf, stack canaries, the Jaguar instructions), for the base executable (`--range lo:hi` for one region) or a built object; the instrument behind docs/DECISIONS.md |
| `generation_census.py` | per-function compiler-generation votes over a text range (3.3 marks against 3.4-and-later marks) and the stretches they form (docs/DECISIONS.md D22) |
| `nid_names.py` | names the executable's imports by recomputing NIDs (SHA-1 of the name and the public suffix, base64) for the candidates in `config/nid_candidates.txt` and `tools/ext/nid_candidates.txt`; writes `config/imports.<slug>.txt`; `--name` prints one NID, `--check <file>` tests a list |
| `fetch_llvm.sh` | fetches a prebuilt upstream LLVM release (3.3 to 9.0.0, each pinned by SHA-256) into `tools/cc/llvm-<version>/`, and the `libtinfo.so.5` those binaries need into `tools/cc/shim/` (Debian's libtinfo5 package, extracted); `setup.sh` runs it for 3.3 and 3.7.1 (the game module also runs the prebuilt 3.7.1's `llvm-nm`) |
| `build_llvm.sh` | `[<version>] [--verify] [--force]`: builds upstream LLVM + clang (3.7.1 default; 3.3, 3.6.2 and 4.0.0 known) from the release tarballs, SHA-256 pinned, with the version's patches under `tools/patches/` applied (the host patches, then the others), into `tools/cc/llvm-<version>-src/`, and for 3.7.1 `llvm-link` and `opt` into `tools/cc/llvm-3.7.1-src-tools/bin/` (the game module's link and link stage); `--verify` compiles every probe TU and every source under `src/` with both the from-source and the prebuilt release under every flag line and requires identical disassembly and relocations (the check of a build made with the host patches alone). | `patches/` | what `build_llvm.sh` applies to the release sources, `llvm-<version>-<what>-<nn>-*.patch`: the host patches (`host`: a few lines each so 2013-2017 LLVM sources build with gcc 14 and Python 3; none changes code generation) and the patches that do change it, each with its evidence in its header: 3.3's twelve backports of later upstream changes, 3.7.1's twelve (four PS4 items, six forward ports of upstream changes, D81; one local rule of the two-stage module, D83; one of the scheduling model, D84; a second local rule of D83, tlsbonus, was removed by D87). ## The gate's cache

`check_elf.py --gate` (and `--progress`) keep the answers of the gate's costly computations in
`build/<slug>/gate-cache/` (never committed) and reuse one only when every input it is a function of
hashes the same (`base_elf.py`, "the gate's cache"). It trusts nothing but SHA-256 hashes of contents:
never a path, a size or a time. Every key also holds the tools' digest: every file under `tools/` (not
`tools/cc`, `tools/ext`, `tools/ghidra`), the Python version and the capstone and pyelftools versions,
so a change to any tool makes every entry a miss. What is kept, and its key:

| kind | the answer | its key, besides the tools' digest |
| --- | --- | --- |
| `vptr` | the vtable address points a cited constructor stores (`vtable_names.py` walk, D14's proof) | the base executable's bytes, the function's address and its size in the table |
| `objfuncs`, `objdata`, `objview` | an object file's functions (bytes and relocations), its data objects, and its symbols, sections and relocations as the layout reads them | the object file's bytes |
| `row` | one row's comparison (`match_check.compare`: score, counts, wrong targets) | the function's bytes and relocations, the base's bytes at the row's address and the address, and for every symbol the relocations name what the base answers this run (its address or the refusal, its GOT slot, a thread-local's offset slot): the resolutions are computed every run, so a row whose callee's row changed is a miss and a row added elsewhere changes nothing |
| `table` | the text of a generated table (`gen_data_inc.py`, run with its depfile as ninja runs it) | the base, the schema, data, function, vtable and import rows, the `c++filt` binary, the schema row, the bytes of every header the depfile says the run read and the names of every file under `src/include/` (where an include resolves); reused only when the file still holds that text |
| `local` | the proof of the local data rows (`module_boundary.local_proof`) | the base, the function table and the rows |

Not cached, computed every run: the compile freshness checks and ninja, the game module's per-unit
views (header statics, compiler-given aliases), the layout of every claimed function and data object
with its relocations resolved, and the whole-image comparison of every loaded segment, byte for byte
(it is cheap and it is the gate's last word). `--progress` reuses the last gate's whole answer
(`build/<slug>/gate.pickle`) only when the tools, the base, every `config/*.<slug>.txt`, every claimed
unit's object and the game module's `symbols.txt` and `.ll` files hash as they did after that gate. `--full` (`tools/build.sh gate-all --full`, or
`TLG_GATE_FULL=1`) neither reads nor writes the cache; deleting the directory changes nothing but time.
