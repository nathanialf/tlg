# tools/

Every file in this directory, with what it does. One tree may carry several
targets (a target is configured when `config/sha256sums.<slug>.txt` exists);
the tools work on the target `tlg_version.py` reports (`VERSION=<slug>`, or
the first configured one, `base`), and the config, base file, build
(`build/<slug>/`) and progress (`docs/<slug>/`) paths follow that slug.
`tools/ext/` and `tools/ghidra/` are fetched by `setup.sh` and not tracked.
`../build.sh` at the repository root runs `setup.sh` and `extract_pkg.sh` when
their output is missing, then `build.sh verify` or `setup` and ninja, whose
last step is the gate.

| tool | what it does |
| --- | --- |
| `setup.sh` | idempotent host setup: the venv from `requirements.txt`; the pinned tools into `tools/ext/` (a user-local .NET 8 runtime and LibOrbisPkg's PkgTool.Core, objdiff-cli) and `tools/ghidra/` (Ghidra 12.2); the compilers, LLVM 3.3 and 4.0.0, via `fetch_llvm.sh`; a check for the host's LLVM 19 and JDK 25; the git hooks |
| `requirements.txt` | the venv's Python packages: pyelftools, capstone, ninja, clang-format |
| `install_hooks.sh` | writes the pre-commit hook (`check_no_rom.sh`, `check_dev_native.py`, `format.sh --check` on the staged sources, then `build.sh gate-all` and `build.sh progress-all` when a staged path can affect the build) and the pre-push hook (`build.sh gate-all` on the pushed tip) |
| `extract_pkg.sh` / `extract_pkg.py` | extracts the user's package (`baserom/TLG_BASE.pkg`) with PkgTool.Core to `baserom/<slug>/app/`, copies out the executable, `param.sfo` (a PKG entry) and the modules, converts the fake-signed SELFs to ELF (`unfself.py`), checks the content id, and records or verifies the SHA-256s in `config/sha256sums.<slug>.txt` |
| `unfself.py` | fake-signed SELF to plain ELF: the ELF headers verbatim and each segment at its `p_offset`; refuses encrypted or compressed entries. Output byte-identical to the reference `ps4_unfself` for every file of this target |
| `sfo.py` | reads a `param.sfo` and prints its fields |
| `tlg_version.py` / `tlg_version.sh` | the target slug (`VERSION`, or the first configured one) and the configured ones, its base file, build, `config/sha256sums.<slug>.txt` and `docs/<slug>/` paths, and the table of each target's package and how messages name it, for the Python and shell tools |
| `verify_elf.py` | checks a file's SHA-256 against `config/sha256sums.<slug>.txt` |
| `survey_elf.py` | the executable's map: every function's address, size and name from `.eh_frame` into `config/functions.<slug>.txt`; the SCE program headers (SDK version, original output path, linked libraries), the dynamic imports and needed modules, and the source paths in the strings into `build/<slug>/survey.json`; `--md` prints `docs/SURVEY.md` |
| `source_homes.py` | which source file each function came from, where the executable says so: the `__FILE__` strings a function loads by RIP-relative `lea`, mapped from the original roots to `src/<dir>/`, into `config/homes.<slug>.txt`; `--md` prints the summary in `docs/TARGETS.md` |
| `text_residue.py` | the text segment between the functions the unwind tables name, classed as padding, a function without an unwind entry that a live reference reaches (two static initializers), or linker residue (discarded code left in the image with zeroed relocations, tails cut mid-instruction), into `config/residue.<slug>.txt`; `survey_elf.py` adds the function rows to the table (docs/DECISIONS.md D13) |
| `vtable_names.py` | which class each vtable belongs to, where the executable says so: the vtable address point each Havok type-info registration stores beside its type name (by `lea`, or read from a temporary built through the class's finish constructor), into `config/vtables.<slug>.txt`, which the gate resolves `_ZTV<class>` relocations against (docs/DECISIONS.md D12); lists the vtables constructors store that no type info names, with the evidence at hand; `--check` verifies the rows of `config/vtables.derived.<slug>.txt` (vtables named by ruling, D14) against the constructor each cites, and the vtable of every library instantiation the claimed rows are members of (std::function's implementation for a lambda: the rows sit in their slots of one base vtable, a claimed slot-0 row stores its address point; one whose slot 0 is not claimed is listed as pending) |
| `rename_rows.py` | `<tu> [--rename OLD=NEW] [--write]`: re-points the symbol column of a unit's rows that name members of a lambda's std::function implementation after the unit renamed the enclosing function (`--rename`) or renumbered its lambdas (`$_<n>` counts the whole file's): compiles the unit, lists its instantiations by (enclosing function, order), and assigns the stale rows' instantiations in order to the object's, taking the one assignment under which every re-pointed row compares equal to the base; refuses none or several; prints without `--write` |
| `build.sh` | `setup` (delete `build/<slug>/`, verify the hashes, write `build.ninja`), `verify`, `regen`, `clean`, `distclean`, `progress` (runs `check_elf.py --progress`), `gate-all` (every configured target: base files required, then setup, ninja, gate), `progress-all` |
| `gen_ninja.py` | writes `build.ninja`: a `cxx` edge per source under `src/libs/` (`compile_cpp.sh`) to `build/<slug>/obj/<path>.o`, an `ir` edge per source under `src/game/` and one `game_module` edge to `build/<slug>/game/module.o` (`game_module.py`), a `gen_data` edge per row of `config/data_schema.<slug>.txt` (`gen_data_inc.py`, an implicit input of its TU's compile), and the default `gate` target, `check_elf.py --gate` |
| `gen_data_inc.py` | `D_<hex>` or `--all`: writes a claimed table's initializer rows into `build/<slug>/gen/D_<hex>.inc` from the user's executable, by the record type and count of its row of `config/data_schema.<slug>.txt` (a struct of a header under `src/include/`): integers decimal, floats as the shortest text that reads back to the same bits, enums by enumerator, a pointer slot by the base's RELATIVE relocation (a char pointer to a printable string as the literal, a function by its name, other data as `&D_<hex>`; a vtable or an import stops it); `--depfile` for ninja. The owning TU includes the file between the braces of the definition (docs/DECISIONS.md D18) |
| `compile_cpp.sh` | compiles one source with the flags `config/flags.<slug>.txt` gives its longest matching prefix; the compiler is the release the prefix's `cxx=<version>` names (3.3 for `src/libs/`, 4.0.0 for `src/game/`), else `TLG_CXX`, else the prebuilt 4.0.0; `build/<slug>/` is on the include path for the generated `gen/D_<hex>.inc` files; `--ir` writes a game unit's unoptimised bitcode (and its text) for the module, `--codegen <prefix>` runs the prefix's `-O2` pipeline and code generation over a linked module |
| `game_module.py` | builds the game region as one module (docs/DECISIONS.md D50): the stand-in definitions of the game objects no file defines yet (protected, zero-initialised, writable; from `config/modules.<slug>.txt`), `llvm-link` of every unit and the stand-ins, one `-O2` pipeline and code generation to `build/<slug>/game/module.o`; refuses a name two files define; writes `build/<slug>/game/symbols.txt` (what each unit defines); `--single` the module of one file, for the inner loop. A name the compiler gives (`COMPILER_LOCAL`: clang's array-destroy helper `__cxx_global_array_dtor`, `.1`, ...) is renamed by the link by one counter over every unit; its row names the unit's own spelling (the unit's IR and single-file object), and `match_check.py` proves the module symbol for it |
| `module_boundary.py` | writes `config/modules.<slug>.txt` from the base: which addresses of the data are the game's and which the libraries', the CRT's or the GOT's, from a census of every RIP-relative operand by the region of its instruction (a cut per data area, the exceptions carved out); `--check` verifies the file |
| `fingerprint.py` | compiler fingerprints over the whole disassembly (cdqe vs movsxd, store merging, vzeroupper, ud2 after call, int 0x41, frame pointers by leaf/non-leaf, stack canaries, the Jaguar instructions), for the base executable (`--range lo:hi` for one region) or a built object; the instrument behind docs/DECISIONS.md |
| `generation_census.py` | per-function compiler-generation votes over a text range (3.3 marks against 3.4-and-later marks) and the stretches they form (docs/DECISIONS.md D22) |
| `nid_names.py` | names the executable's imports by recomputing NIDs (SHA-1 of the name and the public suffix, base64) for the candidates in `config/nid_candidates.txt` and `tools/ext/nid_candidates.txt`; writes `config/imports.<slug>.txt`; `--name` prints one NID, `--check <file>` tests a list |
| `fetch_llvm.sh` | fetches a prebuilt upstream LLVM release (3.3 to 9.0.0, each pinned by SHA-256) into `tools/cc/llvm-<version>/`, and the `libtinfo.so.5` those binaries need into `tools/cc/shim/` (Debian's libtinfo5 package, extracted); `setup.sh` runs it for 3.3 and 4.0.0 |
| `build_llvm.sh` | `[<version>] [--verify] [--force]`: builds upstream LLVM + clang (4.0.0 default, 3.6.2 known) from the release tarballs, SHA-256 pinned, with the host patches under `tools/patches/` applied, into `tools/cc/llvm-<version>-src/`; `--verify` compiles every probe TU and every source under `src/` with both the from-source and the prebuilt release under every flag line and requires byte-identical objects. The instrument for reproducing a compiler behaviour no release has (docs/DECISIONS.md D6); none is needed today |
| `patches/` | the host patches `build_llvm.sh` applies so 2015-2017 LLVM sources compile with gcc 14: one per release, each a few lines with its reason in the header |
| `compiler_probe.sh` | compiles a TU of candidate functions (`tools/probe/batch*.cpp`, functions named as their rows) with every release under `tools/cc/` and the host clang, and scores each function against the base; `PROBE_FLAGS` overrides the flags. The experiment behind the compiler choice (`docs/TARGETS.md`) |
| `probe/` | the probe batches and `summarize.py`, which turns `match_check.py --json` lines into one score line |
| `base_elf.py` | the base executable's facts the match tools share: text segment, function table, every import's PLT stub and GOT slot (from the SCE dynamic tables), a thread-local's GOT slot by its thread-pointer offset (D23), `__dso_handle` from the base's own exit registrations (D25), a byte search for literals, and the address of a symbol by its mangled or bare name, a vtable of a library instantiation (`INSTANTIATION_SLOTS`) by the base vtable that holds its claimed rows in their slots, its slot-0 row claimed and storing it |
| `layout_link.py` | rebuilds every loaded segment (`.text`, `.relro`, `.data` with its `.bss` tail): the base's bytes, with every claimed function (`config/matched.<slug>.txt`) and data object (`config/data.<slug>.txt`) laid out at its address and its relocations resolved as the original link did (function table, `D_<hex>`, PLT stubs, GOT slots, literals found in the base; a data pointer slot must carry the base's dynamic relocation); writes `build/<slug>/<segment>.bin` and `layout.json` and compares each segment with the base byte for byte; a reference to a compiler-given function resolves through the row its proven alias belongs to (a wrong alias moves the owner's field). The gate (docs/DECISIONS.md D7, D8) |
| `match_check.py` | one function, or every function of a TU (`--all`), against the base: the compiled function's instructions (from the object's symbol and its relocations) and the base's at the function's address, compared in step with only the relocated fields masked (after the linker's two relaxations, GOT load to lea (D10) and TLS general dynamic to initial exec (D23), are applied to the object), and every masked field the base can place checked for the right target (a wrong callee fails whatever the score); the score is the share of equal instructions, 1.0 a match; `--diff` prints the first difference in context. A game row naming a compiler-given function (`__cxx_global_array_dtor.2`, the unit's own spelling) is compared at the module symbol `compiler_local_aliases` proves: the one local function of that name with any `.N` whose relocations reach exactly the unit's own named objects the IR body reaches (D17's attribution) and which every stably named function referencing it in the IR references in the module; none or several is a refusal that says which fact failed |
| `quick_diff.sh` | `<tu> <function> [<symbol>] [--module \| --both]`: compile the TU and show the function's diff; the inner loop (a game unit: a module of that file and its stand-ins; `--module` the whole game module, `--both` each and whether they differ; a compiler-given function is named by the unit's own spelling in both) |
| `check_elf.py` | `--gate`: every row of `config/matched.<slug>.txt` must score 1.0 with correct targets, and the rebuilt text segment (`layout_link.py`) must equal the base byte for byte; `--progress`: `docs/<slug>/progress.json` (schema 2: groups by source directory, `unassigned` in 1 MiB ranges), `docs/<slug>/PROGRESS.md` and README.md's badge row |
| `check_dev_native.py` / `dev_native_allow.txt` | refuses crutches in the staged sources: inline asm, `register` pins, codegen-steering attributes, pragmas and builtins, empty `do { } while (0)`, symbol aliases, `volatile` without a reason in a comment; the allowlist holds ruled exceptions with their reasons, reported on every run; `--self-test` runs the fixed cases. In the pre-commit hook (docs/DECISIONS.md D9) |
| `check_no_rom.sh` | IP guard: refuses packages, executables, modules, `param.sfo` and other package files by extension and name, ELF/SELF/PKG magic, large binaries, raw byte-array initializers in tracked sources, and runs of hex directives |
| `format.sh` | clang-format with the tracked `.clang-format`; `--check` for the pre-commit hook |
